0. RÉSUMÉ EN 10 LIGNES
--------------------------------------------------------------------------------
- Produit : "signw", plateforme TIERS DE CONFIANCE pour les marchés.
- Elle certifie des AGENTS (entreprises, prestataires, personnes) pour que le
  PRINCIPAL (client, maître d'ouvrage, acheteur public) sache si l'agent a
  réellement fait ce qu'il prétend et s'il est capable de réaliser un projet
  donné pour un budget donné.
- signw NE FAIT PAS l'audit elle-même dans l'application : la plateforme
  (1) demande les pièces justificatives, (2) les range dans un dossier,
  (3) fait vérifier ce dossier par une équipe d'AUDITEURS, (4) délivre ou refuse
  une certification, (5) publie le résultat de façon transparente.
- Premier secteur : BTP / construction pour les MARCHÉS PUBLICS (Cameroun).
- Architecture extensible : l'ADMIN peut créer de nouveaux secteurs et
  construire lui-même le formulaire de pièces à fournir (form builder).
- 4 espaces : Public (visiteurs), Agent, Principal, Auditeur, + Admin.
  (5 rôles au total, voir section 3.)
- Technologie imposée : HTML + CSS + JavaScript PUR (vanilla). Pas de framework
  de build, pas de backend. Données simulées en JS + localStorage.
- Objectif : prototype "vite fait mais professionnel", démontrable en 5 minutes,
  100 % fonctionnel hors-ligne en ouvrant index.html.
- Langue de l'interface : FRANÇAIS (devise : FCFA / XAF).
- L'ancienne interface (SIGNUUM, 2019) est jugée datée : on la remplace par
  une UI moderne et une UX fluide (voir sections 4 et 5).
- Le prototype doit raconter une HISTOIRE claire : "asymétrie d'information
  réduite grâce à un tiers de confiance" (voir section 1).

1. CONTEXTE ET PROBLÈME RÉSOLU (à connaître pour écrire les textes du site)
--------------------------------------------------------------------------------
1.1 Le problème : l'ASYMÉTRIE D'INFORMATION
Sur un marché, le vendeur (l'agent) connaît la vraie qualité de ce qu'il offre ;
l'acheteur (le principal) ne la connaît pas. Conséquences décrites en économie
de l'information :
  - Sélection adverse (Akerlof) : les bons prestataires sont noyés parmi les
    mauvais, car l'acheteur ne sait pas les distinguer.
  - Signalement / "signaling" (Michael Spence) : un agent compétent a intérêt à
    émettre un signal crédible de sa qualité (ex. un diplôme, une certification).
  - Filtrage / "screening" et asymétrie (Joseph Stiglitz) : le principal doit
    mettre en place des mécanismes pour vérifier la qualité avant de contracter.
  - Risque moral : l'agent peut ne pas livrer ce qu'il a promis après signature.
Dans les marchés publics de BTP : entreprises "fantômes", matériel déclaré mais
inexistant, références de chantiers gonflées, capacité financière insuffisante
pour le montant du marché, travaux mal exécutés, surcoûts.

1.2 La solution signw
signw joue le rôle de TIERS DE CONFIANCE indépendant :
  - Elle transforme des déclarations de l'agent en PREUVES vérifiées.
  - Elle publie un SIGNAL crédible et standardisé (statut + score + badge).
  - Elle permet au principal de tester l'ADÉQUATION entre un projet (budget Y,
    besoins X) et la capacité réelle de l'agent (module "Adéquation projet").
  - Résultat : principal et agent sont au MÊME NIVEAU D'INFORMATION.

1.3 Ce que signw n'est PAS
  - Pas une place de marché transactionnelle (pas de paiement de contrat).
  - Pas un outil d'audit automatique : l'audit est humain (équipe d'auditeurs).
    L'application organise, trace et rend transparent le processus.

1.4 Message à faire passer sur la page d'accueil
  Slogan principal : "Vérifiez avant de contracter."
  Sous-titre : "signw certifie les entreprises et prestataires sur preuves, pour
  que chaque marché soit attribué au bon acteur, au juste prix."

2. CONTRAINTES TECHNIQUES (NON NÉGOCIABLES)
--------------------------------------------------------------------------------
2.1 Stack
  - HTML5 sémantique, CSS3 (variables CSS, Grid, Flexbox), JavaScript ES2020+
    en modules (<script type="module">) ou scripts classiques.
  - AUCUN framework de build (pas de React, pas de npm obligatoire).
  - Librairies externes autorisées UNIQUEMENT via CDN et seulement si utiles :
      * Chart.js (graphiques)            — OPTIONNEL
      * Lucide ou Font Awesome (icônes)  — recommandé (Lucide via CDN)
      * Google Fonts (Inter + une police d'affichage)
    Prévoir un fallback si le CDN est indisponible (les icônes peuvent aussi
    être des SVG inline).
  - Pas de backend : tout est simulé.

2.2 Persistance
  - Données initiales ("seed") dans /js/data/seed.js.
  - Au premier chargement, copier le seed dans localStorage (clé "signw_db_v1").
  - Toutes les actions (soumettre un dossier, valider une pièce, créer un
    secteur...) modifient localStorage et se reflètent dans les autres espaces.
  - Bouton "Réinitialiser la démo" (dans le pied de page et dans l'espace
    admin) qui remet le seed.
  - Entourer chaque accès localStorage de try/catch.

2.3 Authentification SIMULÉE
  - Page de connexion avec email + mot de passe + sélection du rôle.
  - Aucune vraie sécurité : on vérifie contre les comptes du seed.
  - Ajouter un bandeau "COMPTES DE DÉMO" sur la page de connexion avec des
    boutons "Se connecter en tant que : Agent / Principal / Auditeur / Admin"
    (un clic = connexion immédiate). INDISPENSABLE pour la démonstration.
  - Session stockée dans localStorage ("signw_session").
  - Garde de route : si un espace est ouvert sans bonne session, rediriger vers
    login.html avec un message.

3. RÔLES ET PERMISSIONS
--------------------------------------------------------------------------------
(L'ancienne version avait : Internaute, Utilisateur, Gestionnaire, Administrateur.
 On les remplace par des rôles métier plus clairs.)

R0  VISITEUR (non connecté)
    - Voit : accueil, secteurs, annuaire public des agents certifiés, fiches
      publiques, marchés publics, comment ça marche, vérification de certificat.
    - Peut : créer un compte, se connecter, contacter signw.

R1  AGENT (entreprise, prestataire, personne qui propose un service)
    - Crée et remplit un dossier de certification pour un secteur.
    - Dépose les pièces justificatives, suit le statut, répond aux demandes
      de pièces complémentaires, télécharge son certificat, partage son lien
      public de vérification, candidate à des marchés.

R2  PRINCIPAL (client, maître d'ouvrage, acheteur public)
    - Crée des projets/marchés (budget, secteur, exigences).
    - Consulte l'annuaire, compare des agents, lance le test d'ADÉQUATION
      projet/agent, met des agents en favoris, reçoit les candidatures.

R3  AUDITEUR (équipe de vérification interne à signw)
    - Reçoit des dossiers affectés, vérifie pièce par pièce (valider /
      rejeter / demander complément, avec commentaire et niveau de risque),
      planifie un audit terrain (visite de chantier, contrôle du matériel),
      émet un avis final (recommandation) sur le dossier.

R4  ADMIN
    - Gère utilisateurs, secteurs, formulaires (form builder), affectation des
      dossiers aux auditeurs, barème de score, paramètres, journal d'audit.
    - Valide la décision finale de certification (principe des 4 yeux :
      l'auditeur recommande, l'admin décide).

5. PRINCIPES UX
--------------------------------------------------------------------------------
- Un seul objectif principal par page, un seul bouton primaire visible.
- Le visiteur comprend en 5 secondes : QUI est signw, POUR QUI, POURQUOI.
- Parcours Agent en 3 clics : Connexion → Nouveau dossier → Dépôt de pièces.
- Formulaires longs découpés en ÉTAPES avec sauvegarde automatique ("brouillon
  enregistré il y a 3 s") et barre de progression.
- Validation en ligne (au blur) avec messages explicites en français.
- Chaque action destructive demande confirmation (modale).
- Chaque action réussie → toast + mise à jour visuelle immédiate.
- Toujours indiquer "où je suis" (breadcrumb, onglet actif, étape active).
- Toujours indiquer "ce qu'il me reste à faire" (liste de tâches sur tableaux
  de bord : ex. "3 pièces à fournir").
- Transparence : afficher à l'agent POURQUOI une pièce est rejetée (commentaire
  de l'auditeur visible) et au principal COMMENT le score est calculé (bouton
  "Voir le détail du score").
- Mobile-first : tout utilisable à 360px de large. Sidebar → menu hamburger /
  tiroir. Tableaux → cartes empilées ou défilement horizontal propre.
- Accessibilité : HTML sémantique, labels liés aux champs, focus visible,
  navigation clavier complète (modales avec piège de focus, Échap pour fermer),
  attributs aria (aria-live pour les toasts, aria-current pour la navigation),
  alt sur toutes les images, ne pas transmettre l'info par la couleur seule
  (badges = couleur + icône + texte).
- Performance : images compressées (WebP), loading="lazy", pas de JS bloquant.
- Textes d'interface courts, actifs, sans jargon ("Déposer une pièce", pas
  "Procéder à l'upload du document justificatif").

6.2 Cycle de vie d'un DOSSIER (machine à états — à respecter strictement)
  brouillon ──(agent soumet)──► soumis
  soumis ──(admin affecte un auditeur)──► en_verification
  en_verification ──(auditeur demande compléments)──► pieces_incompletes
  pieces_incompletes ──(agent redépose)──► en_verification
  en_verification ──(besoin de terrain)──► audit_terrain_planifie
  audit_terrain_planifie ──(visite faite)──► en_verification
  en_verification ──(auditeur émet avis)──► en_decision
  en_decision ──(admin valide)──► certifie | certifie_avec_reserves | rejete
  certifie ──(date dépassée)──► expire
  certifie ──(fraude/alerte)──► suspendu | revoque

6.4 Calcul du SCORE DE CONFIANCE (0–100) — js/core/score.js
  Le score est la somme pondérée de 5 piliers (barème modifiable par l'admin
  dans parametres.html ; valeurs par défaut) :
    1. Conformité administrative et juridique ........ 20 pts
       (RCCM, NIU, quitus fiscal, CNPS, non-faillite, agrément sectoriel)
    2. Capacité financière ........................... 25 pts
       (CA moyen 3 ans, bilans, attestation bancaire, endettement)
    3. Capacité technique et matériel ................ 25 pts
       (liste du matériel avec preuves de propriété, adéquation au secteur)
    4. Références et expérience ...................... 20 pts
       (projets similaires avec PV de réception / attestations de bonne
        exécution, ancienneté, nombre de projets)
    5. Ressources humaines clés ...................... 10 pts
       (CV, diplômes, contrats du personnel clé)
  Chaque pilier = (somme des points des pièces VALIDÉES) / (points possibles).
  Une pièce "validée" rapporte 100 % de ses points ; "validée avec risque
  moyen" 70 % ; "risque élevé" 40 % ; rejetée/non fournie 0 %.
  Niveaux : Or ≥ 85 · Argent 70–84 · Bronze 55–69 · < 55 : non certifiable
  (ou "avec réserves" si ≥ 55 et pièces critiques manquantes mineures).
  Afficher le score en jauge circulaire + le détail par pilier (barres).
  Chaque champ du form builder a un "poids" qui alimente ce calcul et un
  "pilier" (liste déroulante) auquel il est rattaché.

6.5 Calcul de l'ADÉQUATION projet ↔ agent (le cœur de la valeur — adequation.js)
  Entrées : un Projet (budget Y, exigences) et un Agent certifié.
  Règles (chacune produit un sous-score 0–100 et un message clair) :
   a) Capacité financière : ratio = budget / caMoyen3ans. Idéal ≤ 0.5 ;
      acceptable ≤ 1 ; risqué ≤ 1.5 ; insuffisant > 1.5.
   b) Charge en cours : somme des marchés en cours de l'agent + budget du projet
      comparée à 2 × caMoyen3ans (alerte "surcharge" au-delà).
   c) Expérience similaire : nb de projets de nature et taille comparables
      (≥ 50 % du budget) vs exigence du projet.
   d) Matériel : chaque équipement requis vs possédé ET vérifié (afficher un
      tableau requis / possédé / vérifié, avec coche verte ou croix rouge).
   e) Personnel clé : profils requis vs profils vérifiés.
   f) Niveau de certification vs certification minimale exigée.
   g) Cohérence prix : OPTIONNEL — comparer le budget au coût moyen au m²/km
      du secteur (données fictives du seed) et signaler budget sous-évalué.
  Verdict global : ≥ 80 "Adéquat" (vert) · 60–79 "Adéquat sous réserves"
  (or) · < 60 "Insuffisant" (rouge). Afficher les points bloquants en tête.
  Texte final lisible par un non-technicien : "Cet agent peut réaliser le projet
  pour 480 M FCFA ? OUI avec réserves : matériel de terrassement insuffisant".

6.6 Règles diverses
  - Validité d'une certification : 12 mois (paramétrable).
  - Un agent peut avoir plusieurs dossiers (un par secteur), un seul actif par
    secteur.
  - Code de vérification public : "SGW-AAAA-NNNNN". La page verifier.html
    affiche : valide / expiré / suspendu / inconnu.
  - Format monétaire : "480 000 000 FCFA" ; abréviations "480 M FCFA" dans les
    cartes/graphiques. Dates : "14 octobre 2026".

10. COPYWRITING (ton et exemples)
--------------------------------------------------------------------------------
Ton : clair, factuel, rassurant, institutionnel mais humain. Tutoiement
INTERDIT, vouvoiement partout. Phrases courtes. Pas de jargon.
Exemples :
  - Bouton agent : "Me faire certifier"   - Bouton principal : "Vérifier un
    prestataire"
  - Statut : "Il manque 3 pièces pour soumettre votre dossier."
  - Rejet : "Pièce refusée : la date de validité est dépassée. Merci de
    déposer une version à jour."
  - Succès : "Votre dossier a été transmis. Un auditeur sera affecté sous
    48 h ouvrées."
  - Vide : "Aucun dossier pour le moment. Commencez par créer votre premier
    dossier de certification."
  Rédiger TOUS les textes en français correct (accents, ponctuation). Zéro
  "Lorem ipsum".

11. FLUX DE DÉMONSTRATION (à vérifier avant livraison — script de 5 minutes)
--------------------------------------------------------------------------------
  1) Visiteur : accueil → comprendre → annuaire → fiche d'un agent Or →
     vérifier un code de certificat.
  2) Se connecter en AGENT (agent2) : voir bandeau "pièces incomplètes" →
     redéposer une pièce → resoumettre → voir le statut passer à "en
     vérification" + notification.
  3) Se connecter en AUDITEUR : ouvrir le dossier → valider/rejeter des pièces
     → score qui bouge en direct → émettre l'avis final.
  4) Se connecter en ADMIN : voir la décision en attente → Certifier → un code
     SGW-... est généré → entrée dans le journal.
  5) Admin : form-builder → ajouter un champ au secteur "Énergie" → publier →
     retourner côté agent et constater que le nouveau champ apparaît.
  6) Admin : créer un NOUVEAU secteur ("Éducation") avec 3 champs → il apparaît
     sur secteurs.html et dans le formulaire de création de dossier de l'agent.
  7) Se connecter en PRINCIPAL : créer un projet de 800 M FCFA → lancer
     l'adéquation sur un agent → lire le verdict et ses raisons → comparer 2
     agents → favoris.
  Tout ce flux doit fonctionner sans erreur console, sur desktop ET mobile.
